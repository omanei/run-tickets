# run-tickets

Ночной исполнитель тикетов для процесса скиллов [Matt Pocock](https://github.com/mattpocock/skills):
`/to-spec` → `/to-tickets` → **run-tickets**. Раннер берёт тикеты фичи по одному в порядке
блокеров и для каждого запускает агента два раза, каждый раз с чистым контекстом:
сначала `implement`, потом `code-review` с исправлениями, галочками и `Status: done`. После
каждого шага раннер сам проверяет репозиторий. Если раннер упал, его можно запустить снова, и
он продолжит с того же шага.

```
 next ticket ──▶ implement (новый процесс) ──▶ проверки ──▶ review (новый процесс) ──▶ проверки ──▶ done
      ▲               │ провал: повтор, потом стоп              │ провал: повтор, потом стоп        │
      └───────────────┴─────────── state.json хранит шаг и базовый коммит ─────────────────────────┘
```

- Работает на **Linux, macOS и Windows**: нужны Python 3.9+ и git, других зависимостей нет.
- Агенты: **omp, pi, Claude Code, Codex** и любой другой через конфиг.

## Быстрый старт

```bash
# 1. Установить один раз, на любую ОС (нужен uv: https://docs.astral.sh/uv/)
uv tool install git+https://github.com/omanei/run-tickets

# 2. В корне вашего проекта создать конфиг и проверить, что получилось
cd ~/work/my-project
run-tickets init --agent omp
run-tickets config .scratch/my-feature --prompts

# 3. Запустить
run-tickets run .scratch/my-feature
```

Утром смотрите `run-tickets status .scratch/my-feature` и `.scratch/my-feature/runs/REPORT.md`.

## Установка

Класть скрипт в определённую папку не нужно. Раннеру передаётся путь к каталогу фичи, а
git-репозиторий он находит сам по этому пути. Поэтому запускать его можно из любого каталога.
Способов установки три, выберите один.

### 1. Как команду: рекомендуется

После установки команда `run-tickets` есть в `PATH` и работает в любом проекте.

```bash
uv tool install git+https://github.com/omanei/run-tickets      # или:
pipx install    git+https://github.com/omanei/run-tickets
```

| | uv | pipx |
|---|---|---|
| обновить | `uv tool upgrade run-tickets` | `pipx upgrade run-tickets` |
| удалить | `uv tool uninstall run-tickets` | `pipx uninstall run-tickets` |

- Если репозиторий приватный, используйте адрес `git+ssh://git@github.com/omanei/run-tickets`.
- Если после установки команда не находится, выполните `uv tool update-shell` или
  `pipx ensurepath` и перезапустите терминал.

### 2. Без установки

uv скачает и запустит последнюю версию:

```bash
uvx --from git+https://github.com/omanei/run-tickets run-tickets run .scratch/my-feature
```

### 3. Одним файлом в проекте

Скопируйте `run_tickets.py` в репозиторий, например в `scripts/run_tickets.py`, и
закоммитьте. Тогда у команды будет одна и та же версия раннера.

```bash
python scripts/run_tickets.py run .scratch/my-feature     # Windows: py scripts\run_tickets.py …
uv run scripts/run_tickets.py run .scratch/my-feature     # uv сам подберёт Python
```

Файл самодостаточный. Зависимость `tomli` для Python ниже 3.11 указана прямо в нём
([PEP 723](https://peps.python.org/pep-0723/)), и `uv run` поставит её сам.

## Использование

```bash
run-tickets run    <feature>            # до конца, до блокировки или до остановки
run-tickets run    <feature> --once     # ровно один тикет
run-tickets status <feature>            # что сделано, что следующее, где и почему встал
run-tickets config <feature>            # итоговые настройки и команда агента
run-tickets config <feature> --prompts  # и точные промпты для следующего тикета
run-tickets init   [--agent claude]     # создать .ticket-runner.toml в корне репозитория
```

У `run` и `config` есть флаги `--agent`, `--model`, `--max-time 2h`, `--retries 1` и
`--config <файл>`. Ещё два флага есть только у `run`: `--dry-run` работает как `status`,
а `--adopt-dirty` описан в разделе [«Надёжность»](#надёжность).

Коды выхода:

| Код | Значение |
|---|---|
| `0` | все тикеты сделаны |
| `1` | остановка на проверке |
| `2` | ошибка запуска |
| `3` | запускать нечего, но открытые тикеты остались |
| `130` | прервано |

### Ночной запуск

Агент работает часами, поэтому раннер должен пережить закрытие терминала, а машина не должна
уснуть:

```bash
# macOS: caffeinate не даёт уснуть, nohup переживает закрытие терминала
nohup caffeinate -i run-tickets run .scratch/my-feature > run.out 2>&1 &

# Linux
nohup systemd-inhibit run-tickets run .scratch/my-feature > run.out 2>&1 &
# или внутри tmux / screen

# Windows (PowerShell): отключите сон в настройках электропитания и оставьте окно открытым
run-tickets run .scratch\my-feature
```

Если что-то всё же оборвалось, запустите ту же команду ещё раз.

## Настройка

Всё настраивается в одном файле **`.ticket-runner.toml`**. Обычно он лежит в корне
репозитория и коммитится, тогда настройки общие для команды. Если какой-то фиче нужно своё,
положите отдельный файл в каталог фичи.

Где раннер ищет конфиг, по убыванию приоритета:

1. флаги командной строки (`--agent`, `--model`, `--max-time`, `--retries`);
2. файл из `--config <путь>`;
3. `<каталог фичи>/.ticket-runner.toml`;
4. `<корень репозитория>/.ticket-runner.toml`;
5. значения по умолчанию.

Файлы из пунктов 2–4 не сливаются: раннер берёт первый найденный.

`run-tickets init` создаёт файл, в котором раскомментирован только `agent`, а остальные
ключи с умолчаниями закомментированы. Меняйте только то, что нужно проекту.
`run-tickets config <feature>` показывает, какой файл подхватился, откуда взялось каждое
значение и какой командой будет запущен агент.

### Ключи

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `agent` | `"omp"` | `omp`, `pi`, `claude`, `codex` или имя своего агента из `[agents.<имя>]` |
| `model` | `""` | модель, передаётся агенту флагом `--model` (если задана) |
| `max_time` | `"3h"` | лимит на один шаг; по истечении раннер убивает процесс агента со всеми дочерними |
| `retries` | `1` | сколько раз повторить проваленный шаг в новом процессе |
| `retry_delay` | `"1m"` | пауза перед повтором |
| `report_heading` | `"Step report"` | заголовок отчёта модели в конце шага, например `"Отчёт о шаге"` |
| `report_language` | `"English"` | язык отчёта, например `"Russian"` |
| `preflight` | `[]` | shell-команды, которые должны пройти перед стартом и перед каждым тикетом |
| `notify_command` | `""` | shell-команда для уведомлений (Slack, Telegram…); текст в `$RUN_TICKETS_MESSAGE` |
| `desktop_notify` | `true` | системные уведомления: macOS, `notify-send`, Windows |
| `extra_instructions` | `""` | правила проекта, добавляются в оба промпта |
| `review_extra_instructions` | `""` | правила только для review: как гонять тесты и т. п. |
| `[skills] implement` | `"implement"` | имя скилла реализации |
| `[skills] review` | `"code-review"` | имя скилла ревью; у скиллов из плагинов Claude Code с префиксом плагина: `"<плагин>:code-review"` |
| `[agents.<имя>]` | пресеты | своя команда агента (см. ниже) |
| `[prompts]` | встроенные | полная замена шаблонов `common`, `implement`, `review` |

### Пример конфига

```toml
agent = "omp"
max_time = "3h"
report_heading = "Отчёт о шаге"
report_language = "Russian"

preflight = [
  "docker compose ps --status running --services | grep -q app",
]
review_extra_instructions = """
Run the tests only inside Docker, as the repo's testing docs say.
"""
notify_command = 'curl -s -X POST -H "Content-type: application/json" --data "{\"text\": \"$RUN_TICKETS_MESSAGE\"}" "$SLACK_WEBHOOK_URL"'
```

### Агенты

| `agent` | Что запускается | Вызов скилла |
|---|---|---|
| `omp` | `omp -p --auto-approve --session-dir … --cwd … "<prompt>"` | `/skill:implement …` |
| `pi` | `pi -p --session-dir … "<prompt>"` | `/skill:implement …` |
| `claude` | `claude -p --output-format stream-json --verbose --permission-mode bypassPermissions`, промпт через stdin | `/implement …` |
| `codex` | `codex exec --dangerously-bypass-approvals-and-sandbox -C … -` | текстом |

Пресет `codex` экспериментальный.

От агента нужно три вещи: неинтерактивный режим, отсутствие вопросов на подтверждение и
установленные скиллы. Свой агент или изменённый пресет задаётся так:

```toml
[agents.my-agent]
command = ["my-agent", "--yes", "--workdir", "{{repo}}", "{{model_args}}", "{{prompt}}"]
model_args = ["--model", "{{model}}"]   # подставляется на место {{model_args}}, только если задана model
prompt_via = "arg"                      # "arg" или "stdin"
skill_format = "/{{skill}} {{args}}"    # как агент вызывает скилл
output = "text"                         # или "claude-stream-json"
export_command = []                     # команда выгрузки HTML-транскрипта, если есть
```

Подстановки:

| Где | Что подставляется |
|---|---|
| в `command` | `{{prompt}}`, `{{repo}}`, `{{session_dir}}`, `{{final_file}}` (если агент сам пишет туда финальный ответ, раннер берёт его оттуда) |
| в `export_command` | `{{session_file}}`, `{{html_file}}` |

## Формат тикетов

Формат такой, какой пишет `/to-tickets` при локальном трекере:

```
.scratch/<feature>/
  spec.md
  issues/01-<slug>.md, 02-<slug>.md, …
  runs/            ← создаёт раннер
```

```markdown
# 02: Пользователь экспортирует отчёт

**What to build:** …

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] Критерий приёмки 1
- [ ] Критерий приёмки 2
```

**Статус.** Раннер понимает три записи: `**Status:** x`, `**Status**: x` и `Status: x`.

**Блокеры.**
- **Номером:** `04`, `#4`, `03-slug`. Номера задач вида `PROJ-1234` за блокеры не считаются.
- **Названием тикета:** `/to-tickets` так тоже пишет.
- **Разделом `## Blocked by`** со списком.
- **Без блокеров:** `None (can start immediately)`.
- **Нераспознанный текст:** тикет ждёт и не запускается раньше времени, а `status`
  показывает этот текст.

**Порядок.** Запускается тикет со статусом `ready-for-agent`, у которого все блокеры в `done`.
Если таких несколько, первым идёт тикет с меньшим номером.

**Открытые тикеты.** Тикеты в `needs-info`, `needs-triage`, `ready-for-human` и без статуса
не пропадают. Они и всё, что от них зависит, остаются в списке открытых, и раннер выходит с
кодом 3.

**Каталог фичи** может быть закоммичен, а может лежать в `.gitignore`.

## Надёжность

Словам агента о состоянии репозитория раннер не верит и после каждого шага проверяет всё сам.

| Проверка | implement | review | При провале |
|---|---|---|---|
| stash не изменился, ветка та же, история не переписана | ✔ | ✔ | стоп сразу |
| агент вышел с кодом 0 и уложился в `max_time` | ✔ | ✔ | повтор |
| статус всё ещё `ready-for-agent` | ✔ | | стоп сразу |
| есть коммит после базы | ✔ | | повтор |
| статус `done`, ни одного `- [ ]` | | ✔ | повтор; если агент поставил `needs-info`, стоп сразу |
| нет незакоммиченных изменений | ✔ | ✔ | повтор |

**Повтор** — новый процесс агента. В промпт уходят причина провала и отчёт прошлой попытки.
Попыток всего `retries + 1`, после последней раннер останавливается.

**Состояние** хранится в `runs/state.json`. Раннер пишет его атомарно, перед каждым шагом и
после него. Повторный запуск после `Ctrl+C`, `kill -9` или выключения питания:

- **Прерван implement.** implement перезапускается с той же базой, а агент узнаёт, что его
  частичная работа лежит в коммитах.
- **Прерван review.** review перезапускается.
- **Агент успел поставить `done`, но раннер умер до проверки.** Раннер сначала прогоняет
  проверки. Непроверенным тикет не пропускается и заново не делается.
- **Остались незакоммиченные правки.** Раннер не стартует: он не может отличить правки агента
  от ваших. Если это правки агента, запустите с `--adopt-dirty`.

**Lock.** На рабочее дерево git ставится lock `.git/run-tickets.lock`, второй экземпляр не
запустится. Если процесс, оставивший lock, уже мёртв, lock снимается сам.

**Ослабленные тесты.** Добавленные `skip`, `xfail`, `@Disabled`, `#[ignore]` раннер выделяет
в отчёте.

## Что смотреть утром

| Файл | Что там |
|---|---|
| `runs/REPORT.md` | по записи на шаг: результат или причина остановки, длительность, коммиты, подозрительные изменения тестов, отчёт модели |
| `runs/<тикет>-<шаг>-<время>.log` | полный вывод агента (у `claude` весь поток событий) |
| `runs/<тикет>-<шаг>-<время>.html` | транскрипт сессии со всеми вызовами инструментов (omp, pi) |
| `runs/prompts/` | точный промпт каждого шага |
| `runs/events.jsonl` | машиночитаемый журнал |
| `runs/state.json` | где стоит каждый тикет |

## Частые вопросы

**Как перезапустить тикет с нуля?**
- Удалите его запись из `runs/state.json`.
- Если тикет уже `done`, верните ему `**Status:** ready-for-agent`.

**Как пропустить тикет?** Поставьте ему `**Status:** wontfix`. Тикеты, которые от него
зависят, будут ждать: блокер не `done`.

**Раннер пишет `'omp' is not on PATH`.** Агент должен запускаться из того же терминала
командой `omp`, `claude` и т. п. Проверьте командой `run-tickets config <feature>`.

**Windows и `claude.cmd`, `pi.cmd`.** `cmd.exe` не передаёт многострочные аргументы. Поэтому
раннер сам разворачивает npm-обёртку в `node <script>`. Если обёртка нестандартная, задайте
`prompt_via = "stdin"`.

**Безопасно ли это?** Агент работает без подтверждений и без песочницы. Промпт запрещает
`git stash`, `reset --hard`, `clean`, `rebase` и `push`. Раннер замечает последствия таких
действий, но не предотвращает их. Для изоляции запускайте раннер в контейнере или в отдельном
`git worktree`.

**Ограничения:**
- review смотрит диапазон `since <база>` и захватит посторонние коммиты, если они появятся
  между шагами;
- лимита по деньгам нет. У `claude` его можно добавить флагом `--max-budget-usd` в
  `[agents.claude]`;
- логи не ротируются.

## Разработка

```bash
python -m pip install pytest
python -m pytest
```

Вместо модели в тестах работает заглушка `tests/stub_agent.py`. Тесты покрывают:
- порядок тикетов по блокерам, включая блокеры по названию;
- каждую проверку и повторы;
- изменение stash и `needs-info`;
- таймаут с убийством процесса;
- возобновление после остановки и после настоящего `kill -9` раннера;
- stale lock;
- вывод `claude` stream-json;
- конфиг.

CI (`.github/workflows/test.yml`) гоняет тесты на Linux, macOS и Windows с Python 3.9 и 3.13.
